## 文件结构与维护入口

实际实现集中到 `src/lerobot/yzh/wn_a100/`，只有三个业务模块：

| 文件 | 用途 |
| --- | --- |
| `monitor.py` | GPU / 公告数据、通用显示工具、配置保存、命令行参数和主入口 |
| `desktop.py` | 详细面板、悬浮球、轮播和鼠标交互 |
| `remote.py` | 统一的 SSH 配置、训练日志、磁盘统计、终端登录和连接检查 |
| `config.json` | 服务器连接和两份日志的路径；日后改日志位置只编辑这里 |
| `__main__.py` / `__init__.py` | Python 包入口 / 包标识，不另藏业务逻辑 |

启动关系只有一层：外部入口调用 `monitor.main()`；需要界面时才加载 `desktop.py`。
界面直接使用 `monitor.py` 的数据和 `remote.py` 的远程服务，不再跨训练、磁盘、登录三个小模块转调。
SSH 请求的超时、取消、响应大小限制和客户端回收集中在 `remote.py` 的 `_ssh_output()`，不再维护三份重复实现。
训练、磁盘和连接状态仍有各自的独立刷新周期，不会互相阻塞。

上一级目录不再保留监控代码或兼容启动脚本。统一通过本目录的 `__main__.py` 进入 `monitor.main()`：

- `python /path/to/wn_a100` 或 `python /path/to/wn_a100/__main__.py`：不依赖 LeRobot 安装、工作目录或 `PYTHONPATH`。
- `python -m lerobot.yzh.wn_a100`：已安装项目时的包入口。
- `wn-a100-monitor`：安装项目时生成的命令行入口，直接指向 `monitor.main()`。

`monitor.project_uv_command()` 生成直接调用 uv 的桌面命令，固定 uv、项目和根 `.venv` 解释器的绝对路径。`/usr/bin/env` 清理外部 Python、动态库、uv 和 Conda 覆盖变量并设置明确的工具 PATH；随后执行 `uv run --no-sync --no-env-file` 的包入口。桌面和自启动复用此命令生成逻辑，运行时无需 shell 包装脚本。终端日常使用流程页的直接 uv 命令。
测试仍集中在 `tests/yzh/test_wn_a100_*.py`，不混入运行目录。`desktop.py` 在创建 QApplication 前按已加载 PyQt5 的真实目录设置插件路径，以支持仓库的中文路径。
