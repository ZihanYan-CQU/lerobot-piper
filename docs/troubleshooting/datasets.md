# 数据审查、过滤与合并排错

[问题索引](README.md) · [数据处理流程](../workflows/datasets/README.md) · [工具架构](../architecture/dataset-tools.md)

本页说明当前工具的依赖、失败处理与数据边界；正常操作顺序和完整命令在数据处理流程中维护。

## 界面与依赖

| 现象 | 核对与处理 |
| --- | --- |
| 合并面板与审查面板的依赖不同 | 合并默认使用 PyQt5；审查仍是 CustomTkinter / Tk，并要求 Tk 支持 Xft。两者使用根项目环境的 `desktop` 和 `dataset` extra；需要命令行可视化时按流程页准备 `dataset_viz` |
| 合并打开了旧界面，或提示缺 PyQt5 | `auto` 优先 Qt；只有缺 PyQt5 且未使用 `--source` / `--demo` 时才回退到 Zenity（已安装时）或 Tk。检查 `LEROBOT_GUI_BACKEND` 是否指定了旧后端，再按流程页同步依赖 |
| `--source` / `--demo` 被拒绝 | 两个参数仅支持 Qt；显式选择 `tk` / `zenity` 会报错。使用这两个参数或 `--backend qt` 时，缺 PyQt5 会退出，不会改用旧界面 |
| Qt 插件或图形会话错误 | Qt 窗口启动时会设置当前 PyQt5 的插件目录；其他导入错误、插件加载失败或没有图形会话不属于缺 PyQt5 的自动回退条件。保留完整报错，按[环境整理](uv-conda.md)核对实际解释器和外部库变量 |
| 审查缺 CustomTkinter 或 Tk / Xft | `desktop` extra 提供 Python 窗口包，不会替换解释器自带的 Tk。按错误中显示的解释器路径检查 Tk；系统 `python3-tk` 不一定适用于 uv 管理的 Python |

## 审查与过滤

| 现象 | 核对与处理 |
| --- | --- |
| 选了目录仍无法审查 | 选择包含 `meta/info.json` 和 `data/` 的单份数据集根目录；审查要求至少一个 episode 和视频相机。相机视频及其元数据必须一并保留 |
| 跳转编号无效 | 编号范围是 `0` 到 `total_episodes - 1`，输入后按回车或点击“跳转”。无效输入保留当前播放；翻编号页也不会切换当前视频 |
| 连续播放又回到了第 0 集，或播放了红色标记的集 | 连续播放会循环全部 episode，不会跳过待删除集。红色只表示过滤清单，原始数据未被删除；需要停在当前集时用暂停或“播完暂停” |
| 视频加载或解码失败 | 核对该相机文件是否存在，以及 episode 的视频时间范围是否有效；失败后播放停止，不会自动跳过坏集。保持 `meta/`、`data/`、`videos/` 的相对位置，不要按 MP4 数量猜 episode 编号 |
| 无法生成过滤副本 | 至少标记一集删除，并至少保留一集。输出路径必须尚不存在，不能包含源目录或位于源目录内；输出目录最后一级名称仅允许英文字母、数字、点、下划线和连字符 |
| 保存过滤副本失败 | 当前窗口中的删除标记会保留，可根据错误修正目录或依赖后再试。过滤先写临时目录，成功后才移到目标位置；不会原地修改源数据集 |

## Qt 合并面板

| 现象 | 核对与处理 |
| --- | --- |
| 列表找不到数据集 | 扫描源目录的直接子目录及下一层命名空间，不做任意深度递归；也可通过“添加目录”选择单份数据集。缺 `meta/info.json` 或 `data/` 的目录不会作为有效输入 |
| 搜索后数量与可见勾选不一致 | 搜索只隐藏行，不取消已有勾选；隐藏的已选数据仍参与合并。清空搜索检查完整清单，或用“清空勾选”后重新勾选；“全选”只勾选当前可见行 |
| 刷新后手动目录或排序仍在 | 刷新保留手动添加的目录、已有勾选和顺序；它不是清空选择。开始前核对实际勾选清单 |
| 输出没有放在 `--source` 指定目录 | `--source` 只决定扫描位置。输出固定为 LeRobot home 下的 `namespace/dataset`；home 优先取 `HF_LEROBOT_HOME`，再按 `HF_HOME` / 缓存约定确定。以右侧实际路径预览为准 |
| “开始合并”不可点击 | 需至少两份不同的有效输入、合法 Repo ID、存在的 LeRobot 根目录和未占用的输出路径；输出不能位于输入内部。元信息读取失败时也会阻止启动，查看状态栏错误；`--demo` 不执行真实合并 |
| 能开始合并却随后报错 | 列表统计和路径检查不证明完整数据兼容；FPS、特征、机器人类型及实际文件由编辑后端继续检查。展开“运行日志”查看异常和退出码，确认输入元数据与文件一致 |
| 看不到日志，或进度条没有百分比 | 日志默认折叠，开始合并时自动展开，也可手动展开。进度条表示正在工作，不是数据完成比例；最终状态以进程退出结果为准 |
| 停止或失败后输出目录仍存在 | 合并直接写输出目录，停止不会自动清理或回滚，目录可能不完整；“打开输出目录”可打开这样的目录，不能据此判断成功。保留日志，重试时使用新的输出名称，检查后再决定如何处理旧目录 |
| 合并过程中无法关闭窗口 | 先点击“停止合并”，等待进程结束后再关闭；运行期间配置被锁定，不能同时启动另一轮 |

## 数据边界

- 当部分输入已有兼容的标量布尔 `intervention` 时，GUI 为缺少该列的来源补 `False`，并保留已有标记；所有输入都没有该列时不会新增。CLI 默认不补齐，混合演示和 DAgger 时按[合并配方](../workflows/datasets/README.md#命令行显式目录合并演示--dagger)显式设置。
- RECAP sidecar 尚未接入普通编辑 / 合并工具，按 [RECAP 流程](../workflows/recap/README.md)处理，避免附加标注与 episode 索引错位。
