# Piper 从臂 Kp/Kd 实验

适用于本项目固定的 pyAgxArm 驱动和已确认的 S-V1.9-0 固件。这里只增加显式 MIT 位置阻抗控制实验入口，没有经过实机验证，没有自动寻找安全增益，也没有新增重力模型。

## 两条推理路径使用相同的从臂配置

| 路径 | `joint_control_mode=native`（默认） | `joint_control_mode=mit` |
| --- | --- | --- |
| 普通 deployment | 原来的 `move_j` | 从臂显式 `move_mit` |
| DAgger / RECAP 自主推理 | 原来的 `move_js` | 从臂显式 `move_mit`；主臂继续 `move_js` |
| DAgger 暂停、复位、对齐和人工接管 | 原流程 | 原流程；返回原生 JS 保持后再进入人工接管 |

从臂在原来的 EMA / 插值之后切换后端，不再叠加一层滤波。主臂没有新增增益选项。普通 deployment 的 `send_action`（包括通过它发送的复位命令）使用选中的后端；启动校准和底层退出回零仍沿用原流程。

## 启用参数

以下参数新增在 `PIPERFollowerConfig`，普通客户端、DAgger、RECAP 均可使用。现有模型、频率、插值和平滑参数保持不变。

```bash
--robot.joint_control_mode=mit \
--robot.mit_kp='[10,10,10,10,10,10]' \
--robot.mit_kd='[0.8,0.8,0.8,0.8,0.8,0.8]' \
--robot.mit_torque_ff='[0,0,0,0,0,0]' \
--robot.mit_max_tracking_error=0.1
```

**这是一组 SDK 默认增益的语法示例，不是已经确认适合这台机械臂的运行参数。** 必须先验证所选姿态和负载下能够保持，再执行小幅轨迹。`mit_torque_ff` 必须显式填写；全零表示操作者选择不提供外部前馈，不表示驱动自动提供了重力补偿。

使用 JSON 配置时，在客户端的 `robot` 对象内增加同名字段，例如：

```json
{
  "joint_control_mode": "mit",
  "mit_kp": [10, 10, 10, 10, 10, 10],
  "mit_kd": [0.8, 0.8, 0.8, 0.8, 0.8, 0.8],
  "mit_torque_ff": [0, 0, 0, 0, 0, 0],
  "mit_max_tracking_error": 0.1,
  "mit_feedback_max_age_s": 0.2
}
```

这里是 `robot` 对象需要合并的字段，不是完整客户端配置；保留原来的 `type`、相机等字段。

## 第一轮调参

1. 从臂无接触、机械支撑可用时，在当前实测姿态验证所选 MIT 基线能保持。不要用全零关节目标进入 MIT，也不要同时把所有关节增益归零。停止另一个可能下发命令的进程。
2. 对抖动最明显的一个关节，用同一条小幅轨迹比较，其他五个关节维持已验证参数。每组固定频率、速度参考约定和前馈，记录目标角度、反馈角度、跟踪误差、电流及温度。
3. 如果已验证基线为 Kp=10、Kd=0.8，先比较该关节的 Kp=10、9、8，Kd 固定 0.8；选定 Kp 后比较 Kd=0.72、0.8、0.88。每组使用新的启动参数重启客户端；当前实现没有热更新增益。这些值是局部搜索示例，不是统一的六关节建议。
4. 只更改数组中该关节对应的项。没有明显降低振荡，或降低振荡的同时跟踪明显变差，就保留对照参数，不继续盲目降低刚度。
5. 保持与小幅轨迹验证后，再比较相同的模型动作片段和实时闭环。最后验证完整的暂停、复位与人工接管周期。

本实验后端固定 `v_des=0`，Kd 是对实际速度的阻尼。它没有从位置差分生成新的速度前馈，避免在第一次增益比较时同时改变两个因素。

## 边界与失败行为

- 启用 MIT 必须显式填写六个 Kp、六个 Kd 和六个前馈值；未知控制模式、非有限数值和不合法增益在配置阶段拒绝。
- 第一次发送检查反馈固件至少为 S-V1.8-9。没有关节反馈、反馈时间戳异常、反馈过旧、目标超过 SDK 关节限位，或任一关节目标与实测差超过 `mit_max_tracking_error` 时，整个新命令在发送前拒绝。
- 跟踪误差阈值单位为 rad，默认 0.1（约 5.7°）；它是实验的拒绝条件，不是硬件急停，也不保证停止上一次已下发的目标。不要为继续运行而直接放宽它。
- SDK 的 Kp/Kd 量程与真实关节刚度不是同一个概念。没有逐关节标定时，不把旧固件的力矩缩放系数手工套到增益上。
- 这里的 `torque_ff` 是常量偏置，不能代替随姿态、末端负载变化的重力补偿。若降低 Kp 后明显下垂，先解决支撑/重力前馈，不把一组局部参数当作全工作空间参数。
- 限制前馈范围并不限制 PD 加前馈后的总力矩。该补丁没有新增硬件力矩限制或自动故障恢复；新参数需要操作者在实机上验证。

恢复原控制：移除所有 `mit_*` 参数并将 `joint_control_mode` 设回 `native`。从 JSON 中也移除增益和前馈数组，避免误以为原生模式仍在使用这些增益。
