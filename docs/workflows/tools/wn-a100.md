这是一个 Ubuntu/GNOME 桌面小组件，每 3 秒从 `gmcn.cslcqu.cn` 的 JSON 接口获取一次
WN-A100（`server7`）的状态。它直接显示 8 张 GPU 的利用率、显存占用、温度、功耗、进程数和用户。
显存条会按“GPU + 用户”汇总所有进程并用与网页一致的固定颜色分段；条段内标记用户名，卡片右下角
显示每位用户的显存用量。用户名为 `yzh` 的在用卡会显示高亮绿色外框；本服务器有效申请公告
中明确申请的 GPU 显示红色外框。如果 `yzh` 正在使用已被申请的卡，则优先显示橙色外框提醒
占用冲突，内侧保留红色申请标记，不再显示绿色框。

鼠标悬停在 `yzh` 在用卡的显存进度条范围内时，会立即显示该卡上 `yzh` 的进程 PID 与对应指令，
按 PID 分组、去重；同一进程占多卡时会在每张对应卡的提示中显示。不混入其他用户的指令。
训练参数每项各占一行，保留原有引号、参数值和次序；`--参数 值` 保持在同一行，长中文路径自动软换行。
长指令用有滚动条的窗口展示，鼠标可移入窗口滚动、选中文本，或点击“复制文本”；移开后自动隐藏，
也可按 Esc 或点击 × 关闭。数据刷新时更新对应 PID 的指令，不重置未变内容的滚动位置。
PID、进程名和指令从 SSH 登录环境中当前用户的 `/proc` 读取，不再把网页 PID 当作可操作的进程号。
网页 PID 可能属于不同的进程编号环境，不能用作 SSH / VS Code 终端里清除进程的依据，也不按数值差或相似指令猜测转换。
核实信息与训练日志一同每 10 秒刷新，复用既有 SSH 请求，不新增后台模块或连接；
按日志文件的 inode 和进程 `CUDA_VISIBLE_DEVICES` 匹配 GPU，过滤继承日志描述符的数据加载子进程。
未登录、禁用训练日志读取、日志缺失、进程退出或核实结果超过 30 秒时，撤下 PID / 指令并明确提示，不回退到网页数据。
重新登录后必须再次读到当前进程，不能复活断连前缓存的 PID；GPU 网页离线但 SSH 正常时，仍可显示有效的 SSH 核实结果。
指令仅作为文本展示，不会执行，也没有结束进程按钮。它保留实际 argv 参数和正确引用，
不是原始 shell 启动命令：未记录的 `CUDA_VISIBLE_DEVICES`、`nohup`、重定向和后台符号不补造。
分行文本仅供查看、比对，不应当作完整启动脚本直接执行；进程可能随时退出，操作前仍需核实。
信息只在详细面板显存条悬停窗口显示，
不新增卡片文字行，也不加入悬浮球（含其悬停详情）。

窗口使用 Qt（PyQt5）管理最小化、拖动、缩放和透明圆角。界面使用 Pillow 的 FreeType 引擎
进行 2 倍分辨率抗锯齿渲染，中文优先使用 Noto Sans CJK SC；右键菜单与公告全文窗口使用
Qt 的抗锯齿字体。程序不依赖 Tk、浏览器自动化或本地 NVIDIA 驱动。
首次使用先执行 `uv sync --locked --inexact --extra desktop`，将 PyQt5 安装到稳定的项目 `.venv`；`--once` 不需要 Qt。命令在仓库根目录执行。

## 启动

本机已将 **WN-A100 监控** 固定到左侧启动栏：单击图标，或按 Super / Win 键搜索 `WN-A100` 即可。
当前文件管理器会将 `.desktop` 文件当作文档打开，因此不再依赖双击桌面文件，也不修改全局文件关联。
快捷方式直接调用 uv，固定使用根 `.venv`，并清理外部 Python、动态库和 Conda 变量；安装图标不会启用开机自启动。
业务代码仍位于 `src/lerobot/yzh/wn_a100/`；移动仓库后需要更新快捷方式中的项目路径。

在 LeRobot 项目根目录运行：

```bash
uv run --no-sync python -m lerobot.yzh.wn_a100
```

监控运行代码统一位于 `src/lerobot/yzh/wn_a100/`；外层两个旧脚本入口已移除。
终端和桌面启动均由 uv 选择根 `.venv`，环境缺失或依赖报错时按[环境整理记录](../../troubleshooting/uv-conda.md)修复项目环境。

先在终端检查数据，不打开窗口：

```bash
uv run --no-sync python -m lerobot.yzh.wn_a100 --once
```

断网时预览界面：

```bash
uv run --no-sync python -m lerobot.yzh.wn_a100 --demo
```

## 操作

- 拖动顶部移动窗口。
- 拖动四边或四角调整大小；卡片会自动换行，保持所有 GPU 可见。
- 右上角依次为：收起为浮动球、圆角/直角、打开网页、置顶、最小化、退出。
- 浮动球默认直径 128 像素，可在 104–240 像素间调整，不再显示 GPU 利用率。中央每 4 秒轮播一页信息；
  外圈蓝色、内圈紫色，两个加粗完整圆环各自代表 0–100%，使用圆头和端点亮标增强低进度的可见性。
  球面不显示“训练”标题；中央依次为大号百分比、`GPU X`、预计剩余时间三行，颜色与对应圆环一致，
  例如 `16.0%`、`GPU 0`、`21:49:37`（时:分:秒），不再在圆环上单独标卡号。
  鼠标移到蓝色外圈或紫色内圈，会立即显示对应任务并暂停轮播；移开进度环后恢复轮播。
  轮播使用约 480 毫秒的缓入缓出动画：三行文字整组淡出并轻微上移，下一页再淡入归位，
  不交叉混合不同任务的卡号和时间。鼠标悬停会直接打断动画并显示选中的任务，无需等待过渡。
  有效任务的圆环持续更新，轮播只影响中央文字；展开、最小化、隐藏或拖动时暂停轮播。
  缺少时间时显示“待估算”，无法可靠识别卡号时显示 `GPU ?`，长内容自动缩小字号。
  `yzh` 仅占用 1 张卡时，在该卡对应任务和可用 GPU 信息之间轮播；可用页分三行显示数量、
  “可用 GPU”和卡号，不再挤在任务信息下方。卡号较多时用连续区间压缩（如 `0–2、5`），不会丢失编号。
  任务按实际日志与 GPU 关联选择；没有解析到训练进度的日志不生成轮播页或圆环，
  也不能通过圆环悬停切回“GPU ? / 待估算”的空白页。单卡未匹配到有效日志时只保留可用 GPU 等有效信息，
  不拿另一张卡的旧日志顶替；双卡均无进度时改为显示自己的用卡概况，磁盘页按原规则保留。
  网页实时进程信息确认 `yzh` 占用 0 张卡时，隐藏旧训练任务及圆环，在可用 GPU 数量 / 卡号与磁盘用量之间轮播。
  这优先于日志状态：即使旧日志未达到 100%、已清空、尚无训练进度或读取失败，也不显示旧训练进度。
  磁盘页仍要求 SSH 已登录；未登录时改为轮播登录页（详见下方“悬浮球登录页”）。使用 `--no-disk` 时则只显示可用 GPU、停止轮播。
  再次检测到 `yzh` GPU 进程后自动恢复对应任务和正常轮播；GPU 断连时，可用卡页改为显示离线，不拿上次数据当作当前可用卡。
  训练未全部结束且占用两张或更多卡时，球面和悬停详情都隐藏可用 / 空闲卡信息，释放到一张或零张后自动恢复。
  按实际占用卡数判断，同一张卡上的多个进程只计一张；具体训练含义见下方“训练进度”。
  两份日志的实际步数均达到总步数时，隐藏两个 100% 及训练圆环；仍有自己的 GPU 进程时只显示可用 GPU，
  进程全部结束后按空闲规则轮播可用 GPU 与磁盘用量。已完成日志不再更新也保持此显示，
  仍被 `yzh` 进程占用的卡不会被误计为可用卡。
  有自己的 GPU 进程且任一日志开始新训练或重置后，自动恢复原来的圆环和轮播；缺失 / 读取失败的日志不当作已完成。
  使用 `--no-training` 时，0 / 1 张占用显示可用 / 空闲卡数，两张及以上显示自己的已用卡数，
  不会重新显示 GPU 利用率。
  “可用”指 GPU 利用率和显存占用均低于 10%，且没有有效申请，也不包含自己的已用卡；公告尚未加载或获取失败时
  改为显示“空闲”，避免误判已申请的空卡。GPU 断连显示“离线”，不把上次数据当作当前可用状态。
- 在浮动球上按住 `Ctrl` 滚动滚轮，或按 `Ctrl`＋加减号，每次增减 8 像素；右键“调整悬浮球大小”
  可输入具体直径并实时预览，取消会恢复原尺寸和位置。文字、训练圆环和鼠标区域一起缩放，
  保持圆形；放大时自动避开屏幕边缘。右键可恢复默认大小，调整不会改变详细窗口的大小。
- 浮动球绿色环表示 `yzh` 有在用卡，不再显示申请 / 冲突 / 待确认文字、申请红点或橙色冲突环，
  悬停详情也不弹出冲突提醒。连接状态提醒和训练进度保留；详细窗口的申请红框、冲突橙框不变。
  悬停显示平均显存、你的卡号及显存总量，
  并逐条配对显示申请的卡号和截止时间（不加时区文字）。
- 单击浮动球展开，拖动它移动；展开后恢复原详细窗口位置和大小。`Ctrl+M` 或右键菜单也可切换。
  收起后 GPU 和公告仍按原频率刷新，仅暂停不可见的公告滚动；保留原来的任务栏最小化功能。
- 轮播新增 `yzh` 磁盘页，中央仅两行 `2.3T/3T`、`76.7%`，不显示额外标题或用户名。
  空闲时轮播可用 GPU、磁盘；单卡时轮播任务、可用 GPU、磁盘；双卡时轮播两份任务、磁盘，沿用平滑过渡和圆环悬停切换。
  两份训练日志均完成但自己的进程尚未退出时，暂停磁盘轮播页，只显示可用 GPU；进程全部退出后自动恢复磁盘页。
  磁盘始终按原频率后台统计，轮播切页不会额外启动磁盘扫描；超额红框和悬停详情保留。
  占用超过 3T 时，磁盘页文字和整个悬浮球外框变红，悬停提示显示“超额”；切到任务页时红框仍保留。
  成功刷新到配额以内后自动解除警告；读取失败保留上次数据并在悬停提示注明，未超额的旧数据变灰。
  未知用量显示 `…/3T`、`—%`，不冒充零占用。
- 圆角模式同时裁切窗口背景和鼠标区域；最小化后从系统任务栏恢复。
- 顶部公告栏只展示本服务器当前有效的申请和临时公告；默认服务器规则不参与滚动。
- GPU 申请公告的卡号标签、截止时间标签和正文并排显示，截止时间显示本地日期和时分，不附加时区文字。
  未注明截止时间时明确显示“截止 未注明”，不会从公告中其他数字或日期猜测；长正文以省略号收尾，
  不会挤掉标签，点击可查看全文。每条公告的两个标签与正文作为同一组滚动，不混用不同申请的信息。
- 多于一条公告时，每 8 秒自动向上滚动切换；只有一条时静态显示。点击右侧箭头可提前切换。
- 点击公告查看全部全文（包括默认规则）。红框汇总所有有效申请，不随当前显示的公告改变；
  鼠标悬停红框或橙框卡片可查看相应申请内容。申请撤销或到期后，下次公告刷新会自动取消申请标记，
  `yzh` 仍在使用的卡恢复绿色框。公告全文窗口也突出显示卡号和截止时间。
- GPU 默认每 3 秒刷新，公告独立每 30 秒刷新。公告获取失败时保留上次内容。
- `F5` 立即刷新，`Esc` 退出。
- 右键菜单可打开完整网页、切换置顶、复制当前状态或恢复默认位置。
- 详细窗口位置、大小、置顶、圆角设置以及浮动球位置、直径和收起状态在退出时保存在 `~/.config/wn-a100-monitor/config.json`。
- 连接中断时保留最后一次数据，并指数退避重试（最长 30 秒）。

## 登录后自动启动

自启动项直接调用 uv，记录 uv 可执行文件、项目和根 `.venv` 解释器的绝对路径。命令内清理外部 Python、动态库和环境覆盖变量；登录后使用同一项目环境。

```bash
uv run --no-sync python -m lerobot.yzh.wn_a100 --install-autostart
```

已有旧自启动项可重新执行安装命令覆盖。当前生成器保留 `--api-base`、`--server-id`、
`--server-name`、`--interval`、`--training-config`，以及启用的 `--no-topmost` / `--no-training`。
其他本次 CLI 参数（如 `--no-disk`、`--disk-interval`、`--opacity`）不会写入自启动命令。
自定义 `--training-config` 请使用绝对路径，避免登录启动时工作目录不同而找不到文件。
移动仓库、更换环境后，应重新安装自启动项；该操作不会替你安装桌面依赖。

移除自启动项：

```bash
uv run --no-sync python -m lerobot.yzh.wn_a100 --uninstall-autostart
```

## 磁盘配额（只读 SSH）

复用训练日志的 SSH 配置及已登录的共享连接，在 WN-A100 的 `yzh` 会话中直接执行：

```bash
du -sh "$HOME"
```

`$HOME` 在服务器上展开，不统计本机目录。仅允许 `yzh` 用户的 HOME；不修改或删除文件，
不跟随额外的符号链接、不使用表面文件大小，也不会重复扫描来获取字节精度。
按该命令原始输出显示用量，例如 `2.3T/3T`，下方显示 `76.7%`；K/M/G/T 使用 1024 的幂，配额是 3 × 1024⁴ 字节。
`du -h` 输出是近似显示，超额判断依据其报告值；等于 3T 不算超额，报告值大于 3T 才告警。

默认启动后统计一次，然后每 15 分钟独立刷新。`du` 在低优先级后台执行，不阻塞训练日志、GPU 刷新
或窗口动画；一次扫描最多约 3 分钟，超时、权限错误、部分统计结果都不冒充正常用量。
F5 可以立即刷新，正在统计时不会排队启动第二个 `du`。悬停可看统计目录、数据时间和错误原因；
长时间未更新会标为旧数据，最后已知超额的警告在成功获取新数据前保留，并标明“上次”。

只读一次统计、不打开桌面窗口：

```bash
uv run --no-sync python -m lerobot.yzh.wn_a100 --disk-once
uv run --no-sync python -m lerobot.yzh.wn_a100 --disk-once --json
```

`--disk-interval 900` 可调整统计间隔（秒）；`--disk-timeout 195` 可调整一次请求的总超时（秒）。
如果目录中文件很多，可增大超时。`--no-disk` 可禁用统计和磁盘轮播页；`--no-training` 仅关闭训练读取，
不会关闭磁盘页。`--demo` 使用模拟用量，不执行远端 `du`。共享连接失效时，按下方 SSH 登录命令重新登录。

## 训练进度（只读 SSH 日志）

默认读取 [config.json](../../../src/lerobot/yzh/wn_a100/config.json) 中的两个日志，每 10 秒各读取末尾最多 32 KiB，不下载整个日志，
并只读关联到写入日志的进程卡号信息，不修改服务器文件或训练程序：

| 浮动球弧段 | 日志 | 进度 |
| --- | --- | --- |
| 蓝色外圈 / 轮播中的蓝色文字 | `/home/yzh/具身智能/训练日志/Lerobot/training_2.log` | 任务 1 的步数 / 总步数 |
| 紫色内圈 / 轮播中的紫色文字 | `/home/yzh/具身智能/训练日志/Lerobot/training.log` | 任务 2 的步数 / 总步数 |

两份日志均已迁移到上述目录。以后移动日志时，请同步修改 `config.json` 中对应的 `path` 并重启监控；
仅在服务器上移动文件不会更新监控配置。文件缺失时，该任务不会显示进度环或轮播页，错误可在“查看训练进度”中确认。

每个任务都以完整一圈为 100%，均从顶部顺时针增长；两份进度独立计算，不平均，也不把日志文件名当作 GPU 卡号。
进度环使用加粗完整同心环，在 104 像素直径下宽度为 7 / 6 像素，随球的尺寸同比缩放，
低进度也有圆头和小亮标提示真实端点。
使用 `Training: ... 1060/20000 [1:23:27<24:41:33, 4.69s/step]` 中的实际计数，得到 **5.30%**，
不是进度条四舍五入的 5%。支持 ANSI 颜色、中文路径和 `\r` 覆盖式 tqdm 输出。

悬停浮动球可看日志名、精确百分比、当前/总步数和日志提供的预计剩余时间；右键“查看训练进度”
可打开实时详情，并复制重新登录命令。详细窗口的副标题右侧也显示两份进度。
悬浮球主区域每 4 秒切换一份任务的三行文字（百分比、GPU 编号、剩余时间）；悬停对应圆环可立即切换并保持，
移开恢复轮播。仅占用一张卡时，则轮播该卡对应任务与可用卡数量 / 卡号，不轮播另一张卡的旧任务。
所有轮播都采用 480 毫秒的整组文字淡出 / 淡入和轻微位移动画；进度环始终稳定更新，不参与淡出。
去掉原先的大号 GPU 利用率。低于 0.1% 但大于零时显示“<0.1%”，
尚未完成的任务不因小数舍入而提前显示“100%”；没有训练进度的日志不生成任务页或圆环。
仍可在详细训练信息中查看等待 / 文件缺失 / 解析失败原因，不会把未知进度编造为零。
球面不显示申请或冲突提醒，可用卡信息仅在你占用少于两张卡时显示。GPU 卡片和详细窗口原始指标不变。

GPU 编号和时间各占一行；时间直接来自同一条 tqdm 记录中的预计剩余时间（`<` 后的字段），
不按电脑时间制造持续倒计时。颜色始终与该任务进度一致；日志停更或读取失败时，百分比、时间和卡号一起变灰。

GPU 标签会自动识别：先按日志文件的设备号和 inode，找到当前登录用户中 stdout / stderr 写入该日志的进程，
再从它的启动环境中提取 `CUDA_VISIBLE_DEVICES`。同卡数据加载子进程会去重，日志、百分比、时间和卡号
按完整日志路径配对，不按文件名数字、GPU 排序或网页上 `yzh` 的用卡顺序推测。响应不包含完整进程命令或其他环境变量。
GPU UUID 的掩码会通过只读 `nvidia-smi` 转为编号；限制容器造成数字编号可能重映射时，宁可显示 `GPU ?`。
单个任务使用多张卡时显示例如 `GPU 0/1`。日志轮转、截断或新内容出现后，不复用旧任务的卡号；
已完成且内容不变的日志可保留上次验证的卡号，悬停会说明来源。

默认每个日志的 `gpu_index` 为 `null`，表示自动识别，无需手填。只有自动编号因容器重映射无法对应网页时，
才可在该日志配置中将 `gpu_index` 设置为网页上的真实 0–7 编号作为显式覆盖；修改配置后重启监控。

### 悬浮球登录页

未登录或 SSH 共享连接断开时，悬浮球自动增加“登录 / SSH 未连接 / 点击连接”轮播页。
训练进度页、磁盘用量页及训练进度环暂停显示，避免把旧数据当作当前数据；GPU 网页监控不受影响。
你占用少于两张卡时，登录页与可用 GPU 页轮播；占用两张卡时，与自己的用卡概况轮播。
即使当前没有自己的 GPU 进程，未登录时仍保留登录页；登录恢复后，无进程时轮播可用 GPU 与磁盘用量，
不会恢复旧训练进度。禁用磁盘监控时仅显示可用 GPU、停止轮播。

鼠标移入登录页中央会暂停轮播。单击中央（或按 Enter / 空格）打开本机终端，
在那里完成 SSH 密码 / 验证码认证；监控不接收、保存或复制密码。不加入右键登录菜单。
拖动仍只移动悬浮球，点击外围仍展开详细窗口。认证过程中重复点击不会重复打开终端；
认证失败后按终端提示关闭窗口，可在登录页重试。无法打开终端时，悬停查看错误，也可按下方命令手动登录。
登录、连接状态和可用 GPU 页使用独立的较小标题及更宽松的三行间距，避免中文挤压。
不再额外叠加第四行“离线 / 连接中”，连接异常仍通过外框和悬停详情提示。

连接状态在后台独立检查：只复用已登录的共享连接执行无副作用的 `true`，不会偷偷发起新登录。
终端打开或退出本身不算登录成功。验证成功后移除登录页，并立即刷新训练和磁盘数据，
无需重启监控或等待磁盘的 15 分钟周期。退出监控不会关闭登录终端或共享连接。
登录脚本让本次启动的 SSH / 跳板子进程忽略终端挂断信号，避免认证成功后随登录窗口关闭而断线；
仍可用 Ctrl+C 取消认证。终端关闭前还会检查共享连接是否能执行只读操作；验证失败时保留报错，
不会把“命令返回成功但连接已断”误报为登录完成。不修改 SSH 配置，也不保存密码或认证输出。
`--demo` 不进行真实登录；训练和磁盘读取均禁用或切到其他服务器时，不显示此登录页。

首次使用或共享连接失效后，也可在**本机终端**（不是 VS Code 的远程终端）手动执行以下命令：

```bash
env -u LD_LIBRARY_PATH ssh -4 -M \
  -S /run/user/1000/wn-a100-training.sock \
  -o ControlPersist=8h \
  -J jumper@cps.cslcqu.cn:6666 \
  -p 1143 -fN yzh@192.168.1.50
```

监控只复用这个 ControlMaster；找不到共享连接时直接报告错误，不弹密码框、不回退为另一次登录。
SSH 客户端清除 `LD_LIBRARY_PATH`，两个终端的连接命令无需绑定 8080，不影响原有的端口转发。
程序不保存密码或私钥，退出时只停止自己的读取线程和短时客户端，不关闭你的共享 SSH 连接。
共享连接在最后一个复用会话结束后可继续空闲保持 8 小时；监控持续读取时会延长复用。
网络断连或空闲连接关闭后，在终端重新运行上述命令即可，监控会自动恢复。
非 uid 1000 用户需使用自己的 `$XDG_RUNTIME_DIR/wn-a100-training.sock`，配置默认自动使用该目录。

验证真实日志（不打开桌面窗口）：

```bash
uv run --no-sync python -m lerobot.yzh.wn_a100 --training-once
uv run --no-sync python -m lerobot.yzh.wn_a100 --training-once --json
```

等待、停更、断连、traceback、进度重置和“100%”的含义统一见[监控问题记录](../../troubleshooting/README.md)。

配置中的 `interval` / `timeout` / `stale_after` 控制独立刷新、超时、停更阈值。
本地 LeRobot 的断点续训有时让 tqdm 的总数只表示剩余步数；如遇到这种情况，在对应日志条目
把 `step_offset` 从 0 改为该次恢复的准确起始步数，整体进度为 `(当前计数 + offset) / (总计数 + offset)`。
新训练需恢复为 0；程序不会从被四舍五入的 `steps:1K` 文本猜测偏移。默认 0 正好对应当前这两份日志。
默认只在 WN-A100 (`server7`) 启用 SSH 训练读取，切换其他服务器不会混入这两份日志。

## 可选参数

```text
--interval 5       改为每 5 秒刷新
--no-topmost       启动时不置顶
--opacity 0.90     调整窗口透明度
--windowed         使用普通系统标题栏
--once --json      输出一次机器可读 JSON
--training-once    验证一次远端训练进度，不打开窗口
--training-config  指定其他训练日志 JSON 配置
--no-training      关闭 SSH 日志读取，浮动球按占用情况显示可用 / 空闲卡数或自己的已用卡数
```
