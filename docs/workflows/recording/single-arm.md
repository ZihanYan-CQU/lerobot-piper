# Piper 单臂数据采集现场指南

[返回数采导航](README.md) · [设备绑定](../tools/device-bindings.md) · [数据处理](../datasets/README.md) · [问题记录](../../troubleshooting/recording.md)

本指南用于在这台 Linux 电脑上，通过人工操纵 Piper 主臂，带动一台 Piper 从臂完成任务，并将相机画面、机械臂状态和示教动作保存成新的 LeRobot 数据集。适合第一次使用本机代码的操作者。

这里的“单臂”指 **一台执行任务的从臂**；操作时还需要一台供人手操纵的主臂。使用的是本地人工示教采集入口 `lerobot-record`，不需要加载训练好的模型。

本机项目位置为 `/home/cpy/桌面/yzh/piper/lerobot`；在其他副本或机器操作时，先把本页两个 `cd` 和数据目录基础路径改成实际仓库位置。下文沿用该项目在 2026 年 11 月 7 日的默认硬件配置。先完成设备准备，再执行采集命令；不要将整篇文档一次粘贴到终端运行。

## 1 先认识设备和数据

| 名称 | 操作者需要知道的含义 |
| --- | --- |
| 主臂 | 人手操纵的示教机械臂，对应 CAN 接口 `can_master` |
| 从臂 | 跟随示教动作、接触物体并执行任务的机械臂，对应 `can_follower` |
| CAN | 电脑与机械臂通信的接口；主臂和从臂必须分清 |
| 相机别名 | 固定设备名称，避免相机插拔后 `/dev/video0` 等数字编号变化 |
| episode | 一条演示，例如完整地“抓起一个物体并放到指定位置” |
| 数据集 | 多条 episode 的集合，包含视频、状态、动作和任务说明；状态是从臂反馈位置，动作是主臂示教目标 |
| 复位 | 一条演示结束后，让机械臂回到起始位置、将物体重新摆好 |

默认相机配置如下。三路都要可用；只接两路时，原样启动会因缺少第三路相机而失败。

| 相机名称 | 设备别名 | 保存画面的宽 × 高 | 图像旋转 | 帧率 |
| --- | --- | --- | --- | --- |
| `top` | `/dev/video_top` | 480 × 640 | 90° | 30 FPS |
| `wrist` | `/dev/video_wrist` | 640 × 480 | 0° | 30 FPS |
| `down` | `/dev/video_down` | 640 × 480 | 0° | 30 FPS |

`top` 从相机读取 640 × 480 画面，再旋转成竖幅。应通过预览核对实际安装位置和画面方向，不要只根据相机的数字编号猜测是哪一台。

## 2 每次采集前准备设备

### 2.1 准备工作台

1. 按本机原有接线连接主臂、从臂、USB CAN 适配器和三台相机，接通机械臂电源。
2. 固定相机和物体摆放区域，确认画面能看到任务目标及夹爪操作区域。
3. 为机械臂启动、每轮复位和退出时的回零动作留出空间。启动命令执行后会连接并移动机械臂。
4. 结束此前占用机械臂或相机的采集、遥操作、推理和预览程序。同一套设备只运行一套控制程序。

### 2.2 打开终端并进入项目

在 Linux 桌面打开终端，执行：

```bash
cd "/home/cpy/桌面/yzh/piper/lerobot"
```

环境维护先按[环境安装](../setup/README.md)完成 `uv sync --locked --inexact --extra piper-client --extra core_scripts`。下方直接用 `uv run --no-sync` 运行项目 `.venv` 中的采集命令，启动时不安装依赖，无需脚本前缀。每次打开新终端，先执行上面的 `cd`。

### 2.3 核对相机和 CAN 绑定

打开已有设备面板：

```bash
bash src/lerobot/yzh/device_bindings/start.sh
```

在 **RGB 相机** 页签：

1. 刷新设备列表，为 `video_top`、`video_wrist`、`video_down` 选择各自的 RGB 相机。
2. 使用“预览画面”逐一确认。不要选择深度、红外或元数据节点。
3. 如果面板只有 `video_top` 和 `video_wrist`，点击 **＋ 添加别名**，补上 `video_down`。
4. 需要修改绑定时，确保三路映射都在面板中，再点击 **保存绑定**，按系统提示输入管理员密码。保存会替换这个工具管理的整组映射，因此不能只保留新加的一路。
5. 检查完后关闭相机预览窗口，释放设备。

相机别名通常重启后仍有效。已有映射正确时不用反复保存；相机缺少唯一序列号、按 USB 位置绑定时，应保持原有 USB 插口。

在 **机械臂 CAN** 页签：

1. 分别选择主臂和从臂对应的 USB CAN 端口，两者不能是同一个。
2. 保持名称 `can_master`、`can_follower`，波特率均为 `1000000`。
3. 点击 **绑定并激活主从臂**，完成系统授权，确认激活成功。

**电脑重启或 USB CAN 重新插拔后，要重新激活 CAN。** 工具只设置当前运行状态，不会自动配置开机激活。不要照搬另一台机器的 USB 端口编号。

在终端可以做以下只读检查：

```bash
ls -l /dev/video_top /dev/video_wrist /dev/video_down
ip -details link show can_master
ip -details link show can_follower
```

三路相机别名应能找到对应设备；两个 CAN 接口应带有 `UP` 标志，并显示 `bitrate 1000000`。如果缺少接口或别名，先回到设备面板处理。

## 3 设置并启动一个新数据集

### 3.1 先检查采集入口

这条命令只显示帮助，不连接机械臂：

```bash
uv run --no-sync python -m lerobot.scripts.lerobot_record --help
```

正常时会列出 `--robot.type`、`--teleop.type` 和 `--dataset.*` 等参数。若提示 Python 路径不存在或缺少模块，先按[问题记录](../../troubleshooting/recording.md)处理环境问题。

### 3.2 复制启动命令

先将下面 `TASK_DESCRIPTION` 的示例文字改成实际任务，再整段执行。命令使用当前三路相机配置，数据保存在本机；每次执行都会生成新的时间戳名称。

```bash
cd "/home/cpy/桌面/yzh/piper/lerobot"

DATASET_NAME="piper_demo_$(date +%Y%m%d_%H%M%S)"
DATASET_DIR="/home/cpy/桌面/yzh/piper/lerobot/outputs/datasets/${DATASET_NAME}"
TASK_DESCRIPTION="抓起物体并放到目标位置"

printf '本次数据保存到：%s\n' "$DATASET_DIR"

uv run --no-sync python -m lerobot.scripts.lerobot_record \
  --robot.type=piper_follower \
  --teleop.type=piper_leader \
  --dataset.repo_id="local/${DATASET_NAME}" \
  --dataset.root="$DATASET_DIR" \
  --dataset.single_task="$TASK_DESCRIPTION" \
  --dataset.fps=30 \
  --dataset.num_episodes=50 \
  --dataset.episode_time_s=60 \
  --dataset.reset_time_s=60 \
  --dataset.no_stamp=true \
  --dataset.push_to_hub=false \
  --display_data=false \
  --resume=false
```

这条命令启动后会自动连接设备、回零并开始倒计时。**第一条演示不需要按右键开始；看到“正在记录 episode 0”后直接操作主臂。**

命令中的反斜杠 `\` 表示下一行仍属于同一条命令。复制时保留它，且不要在反斜杠后面加空格或注释。

### 3.3 常用参数

| 参数 | 本例取值 | 含义 |
| --- | --- | --- |
| `dataset.single_task` | 实际任务的一句话说明 | 随数据保存，例如“将红色方块放入白色盒子” |
| `dataset.num_episodes` | `50` | 本次要成功保存的条数；重录丢弃的条不计数，软件不判断任务成败 |
| `dataset.episode_time_s` | `60` | 每条最多录制 60 秒，可用右键提前结束 |
| `dataset.reset_time_s` | `60` | 每条之后最多留 60 秒摆物，可用右键提前结束 |
| `dataset.fps` | `30` | 目标采样频率，每秒 30 帧 |
| `dataset.root` | `DATASET_DIR` | 数据实际保存目录 |
| `dataset.repo_id` | `local/时间戳名称` | 数据集标识；这里使用本地命名，不要求登录账号 |
| `dataset.no_stamp` | `true` | 名称已经包含时间戳，不再由程序追加一次 |
| `dataset.push_to_hub` | `false` | 本次只保存到本机 |
| `display_data` | `false` | 不开启额外的实时可视化窗口，相机仍正常采集和保存 |
| `resume` | `false` | 新建数据集 |

第一次只想熟悉流程时，可把条数改成 `2`；`0` 表示不录制，不表示不限条数。其余参数可以继续使用上面的值。实际录制时长不足 60 秒时，任务完成就按右键结束，不必刻意等满时间。

数据集最终目录由程序创建，不要提前执行 `mkdir "$DATASET_DIR"`；新建时该目录必须尚不存在。

## 4 一条演示从开始到保存的完整过程

正常流程如下；最后一条和主动退出时会跳过中间的复位阶段。

```text
连接设备并回零
      ↓
3 秒开始倒计时
      ↓
录制任务  → 人手操纵主臂，从臂跟随，图像和动作正在记录
      ↓ 任务完成按 → / n，或录制时限到达
3 秒回零提示 → 程序回零
      ↓
恢复实验环境 → 摆回物体；这段不计入数据，但主从臂仍可遥操作
      ↓ 摆好后按 → / n，或复位时限到达
保存本条并编码视频
      ↓
显示“episode N 采集完毕”
      ↓
下一条 3 秒倒计时，自动开始
```

按终端提示操作：

| 终端出现的内容 | 当前正在做什么 | 操作者的动作 |
| --- | --- | --- |
| 设备连接、回零等日志 | 初始化主臂、从臂和相机 | 等待连接完成，留出回零空间 |
| `3s 后开始采集 episode 0` | 本条开始前的倒计时 | 物体已摆好，准备操纵主臂；不要抢按右键 |
| `正在记录 episode 0；剩余时间…` | 正式录制 | 连贯地完成一次任务 |
| `主从臂将 3s 后回零` | 即将自动回零 | 等待机械臂回零，避开运动范围 |
| `请在 …s 内恢复实验环境` | 本条结束后的复位阶段 | 重新摆好物体，完成后按一次右键 |
| `episode 0 采集完毕` | 本条已完成保存 | 准备下一条，编号会变为 1 |
| `数据采集完毕`、失能倒计时等 | 整场采集的保存和退出过程 | 按失能提示扶稳从臂，等待“程序结束”和终端提示符恢复 |

**右键结束录制后，数据通常还没有完成保存。** 正常流程会先回零、留出摆物时间，再保存本条。视频编码可能需要等待；不要因为暂时没有新画面就关闭终端。

复位时间结束会自动继续下一条，没有额外的“确认开始”步骤。需要更多摆物时间时，应在下次启动前增大 `dataset.reset_time_s`。

## 5 按键速查

按键在运行采集的终端中使用，不需要按 Enter。建议每次只按一下，观察提示变化后再进行下一步。

| 按键 | 在“正在记录”阶段 | 在“恢复实验环境”阶段 |
| --- | --- | --- |
| **→** 或 **n** | 提前结束本条录制，进入回零和复位；最后一条直接保存退出 | 提前结束摆物时间，保存刚录完的本条，然后进入下一条倒计时 |
| **←** 或 **r** | 标记丢弃本条，经过回零和复位后重新录同一编号 | 丢弃刚才录完但尚未保存的本条，准备重录同一编号 |
| **Esc** 或 **q** | 结束整场采集；已有帧且未标记重录时，保存当前录到的片段 | 结束整场采集；通常保存刚录完的本条；若这条已标记重录，则丢弃 |
| 空格、Enter、↑、↓ | 没有暂停或开始功能 | 没有暂停或开始功能 |
| **Ctrl+C** | 中断程序，当前尚未保存的一条不会按正常流程提交 | 同样可能丢失刚录完、还没保存的一条 |

记住这几个边界：

- **本入口没有暂停后继续同一条的按键。** 录制不顺时用左键重录。
- **左键只能丢弃当前尚未保存的一条。** 已出现“episode N 采集完毕”的历史数据，需要采集结束后用审核工具处理。
- **Esc 不是“丢弃本条”。** 如果任务没做完就按 Esc，未完成的片段也可能保存。
- 在 3 秒倒计时、自动回零或保存过程中，不要连续按键。某些阶段不会立即处理按键，提前按右键或退出可能让下一条还没采到帧就结束。
- 在 Wayland 或远程终端中，将焦点放在采集终端；方向键不灵时可用 `n`、`r`、`q`。使用英文输入模式，不要把采集命令作为后台任务运行。

**Esc 和 Ctrl+C 都不是硬件急停。** 正常退出还会执行保存、回零和失能步骤。出现碰撞风险或异常运动时，按现场设备的急停流程处理；不要等待采集软件完成退出。

### 指示灯提示

灯光用于辅助识别当前阶段：普通数采的绿闪是录制前倒计时，绿常亮是正在录制；完整灯态、复位/退出的区别及开关参数见[指示灯作用与配置](../tools/status-indicator.md)。灯未连接时以终端提示为准。

## 6 四种常见操作情景

### 6.1 完成一条后继续采集

1. 看到“正在记录 episode N”后，操作主臂完成任务。
2. 任务完成，按一次 **→** 或 **n**。
3. 等待回零，看到“恢复实验环境”后摆回物体。
4. 摆好后按一次 **→** 或 **n**，或等待复位计时结束。
5. 等待本条保存和下一条倒计时，再开始下一次演示。

### 6.2 抓取失败或演示录坏了

1. 在录制中按一次 **←** 或 **r**。
2. 等待回零，重新摆好物体。
3. 在“恢复实验环境”阶段按 **→** 或 **n** 跳过剩余等待。
4. 程序丢弃失败片段，下一次仍录同一个 episode 编号。

如果录完后才发现失败，但还处在紧随其后的“恢复实验环境”阶段，也可以按 **←** 或 **r** 丢弃这条。按下后会进入重录准备，因此先把物体摆好再按。

### 6.3 最后一条做好了 想提前收工

有两种正常操作方式：

- 当前任务已经完成、仍显示“正在记录”时，按 **Esc** 或 **q**。程序保存已经录到的内容并退出。
- 已按右键结束录制，当前在“恢复实验环境”阶段时，按 **Esc** 或 **q**。程序保存刚完成的这条并退出。

然后等待视频编码、回零和失能完成。终端会提示从臂失能倒计时，按提示扶稳，避免失能后下落；看到“程序结束”并恢复终端提示符后，再关闭窗口。

### 6.4 当前这一条不要了 也想结束采集

1. 在“正在记录”阶段按 **←** 或 **r**，将本条标记为重录。
2. 等待回零，并明确看到 **“请在 …s 内恢复实验环境”**。
3. 此时按 **Esc** 或 **q**。程序丢弃这条已标记重录的数据并退出；更早保存好的条目保留。

不要连续快速按“左键、Esc”，也不要等到下一条倒计时才操作。这一流程依赖当前仍处在该条的复位阶段。

## 7 采后验收与交付

程序结束后在原终端查看本次输出目录：

```bash
printf '%s\n' "$DATASET_DIR"
```

按[数据集验收](../datasets/README.md#采后验收与交付)核对保存条数、相机字段和视频，再用[多相机审核工具](../datasets/README.md#2-人工审查与过滤)逐条筛选。复制完整的数据集目录，保留 `meta/`、`data/` 和 `videos/` 的相对位置。

## 8 常见问题

相机 / CAN 缺失、方向键无响应、复位与保存顺序、已有目录、帧率、温度和可选指示灯问题集中在[问题记录与排错](../../troubleshooting/recording.md)。审核和过滤步骤只在[数据处理流程](../datasets/README.md)维护。

## 9 现场操作速记

```text
准备：确认三路相机 → 激活主从 CAN → 关闭预览 → 摆好物体
启动：运行新建命令 → 等待连接回零 → 等 3 秒 → 自动开始录制
做好：正在记录时按 → 或 n → 等回零 → 摆物 → 按 → 或 n → 等保存
录坏：正在记录时按 ← 或 r → 等回零 → 摆物 → 按 → 或 n → 同编号重录
收工：完成任务后按 Esc 或 q → 等保存 → 按失能提示扶稳从臂 → 等程序结束
丢弃并收工：正在记录时按 ← 或 r → 等到恢复实验环境阶段 → Esc 或 q
验收：核对 meta/info.json 条数 → 检查三路画面 → 按条审核 → 交付完整目录
```

## 10 维护入口

日常命令见[数采导航](README.md)，目录和调用关系见[人工示教数采结构](../../architecture/recording.md)。此现场流程已按本机 Piper 的录制入口、键盘控制、默认相机配置和退出流程核对。

`DATASET_DIR` 只在设置它的终端中有效；换终端后需重新设置完整目录。也可以在文件管理器中打开 `/home/cpy/桌面/yzh/piper/lerobot/outputs/datasets`，找到对应时间戳的 `piper_demo_年月日_时分秒` 文件夹。
